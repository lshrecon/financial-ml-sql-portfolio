# 재무지표를 이용한 주가 분류와 SQL 데이터 정리

기존 검사 결과를 포함한 일본어 원본 ZIP의 README를 본인 열람용으로 옮긴 문서로, 아래 ‘ZIP’·‘배포 자료’는 일본어 원본 코드 묶음을 뜻합니다.

2026년 10월 9일판. 수정·학습용 사본에서 정리한 채용 검토용 소스입니다. 수업에서 제공받은 원자료는 포함하지 않았습니다. 모든 노트북을 한 번에 실행할 수 있는 완성된 패키지는 아닙니다.

## 목적·구성

수업·교수님에게 제공받은 재무·주가 데이터를 가공하고, PER·PBR·PSR·PCR의 역수, 평균, 순위를 이용해 결정트리와 랜덤포레스트로 분류한 개인 작업입니다. 최근에는 AI의 도움을 받아 계산과 평가를 다시 점검했습니다.

- 현재 분류 대상은 수정주가의 상승·비상승입니다. 계정 손익과 잔금은 별도로 계산합니다.
- `ml_validation.py`: 잔금·이익·가격 방향, 시간순 분할의 공통 처리.
- `KSE_가치팩터_functions.py`: 지표, 순위, 가격 가져오기, 집계.
- `evaluate_price_direction.py`: v2의 제한적인 가격 방향 평가. `evaluate_saved_cohort.py`는 이전 계정 이익 목표의 평가·회귀검사용입니다.
- ML 노트북 3개: 전처리와 원래 실험 구성을 읽기 위한 참고 소스.
- `database/stock_etl.py`와 SQL: pandas로 데이터 형태 정리, MySQL 테이블 설계·적재·연도별 추출. ML은 Excel을 입력으로 사용하며, DB에서 모델로 자동 연결하지 않습니다.

## 수정 예: 잔금은 이익이 아니다

원금 1,000으로 단가 300인 주식을 3주 사고 330에 팔았다면, 잔금은 100이고 주식 매매차익은 90입니다. 이전에는 90에 잔금 100을 더해 이익을 190으로 계산했습니다. 수정 후에는 최종 자산 1,090에서 원금 1,000을 빼 이익을 90으로 계산하고, 잔금은 이익에 더하지 않고 자산으로 유지합니다.

원금 500·주가 600→660이라면 매수 수량은 0주이고 계정 이익은 0이지만, 가격 방향의 정답은 상승입니다. 두 목적에 같은 정답을 사용하지 않도록 분리했습니다. 연도와 회사의 대응, 지정한 월을 벗어난 날짜, 빈 결과, PBR 연도를 잘못 가져오는 문제도 수정했습니다.

## 확인 결과와 한계

| 확인 | 기록된 결과 | 의미 |
|---|---|---|
| ML의 작은 회귀검사 | 33개 통과 | 회계·분할·특징·경계 조건 확인 |
| SQL 전처리의 Python 검사 | 17개 통과 | 자료형·키·저장 실패 등 확인 |
| 실제 MySQL의 합성 자료 검사 | 11개 통과 | DB 제약·적재·대조 확인 |
| 실제 데이터 전수 대조 | 3,784,245행, 불일치 0 | 적재 전후의 날짜·회사명·가격 일치 |

이 결과들은 2026년 10월 AI의 도움을 받은 검증 기록입니다. 33개, 17개, 11개는 서로 다른 범위를 확인한 것이며, 합산한 품질 점수가 아닙니다. 378만 행 대조는 저장의 정확성을 확인한 것으로, DB 처리 속도의 우위나 ML의 예측 성능을 나타내지 않습니다. 이 ZIP에는 전수 대조에 사용한 원자료가 포함되지 않습니다.

2017–2020년의 제한적 검증에서 항상 상승이라고 답하는 기준은 정확도 44.13%·상승 F1 0.6124, 결정트리는 53.68%·0.5384, 랜덤포레스트는 55.36%·0.5371이었습니다. 사전에 선택한 상승 F1에서는 기준을 넘지 못했습니다.

매도가가 결측인 3행을 명시적으로 제외한 13,976행의 제한적 실험입니다. 이전에도 사용한 자료의 재평가이며, 새로운 독립 시험은 아닙니다. 기재된 모델 수치는 10월 8일의 추가 경계 조건 수정 후 재학습한 결과가 아닙니다.

재무정보의 공표·정정 시점, 가격 보정, 당시 종목 집합과 거래 가능 여부, 결측 회사의 회수 금액은 확인되지 않았습니다. 배당·수수료·세금을 포함한 투자 수익, 모든 노트북의 일괄 실행, DB 운영 성능은 검증하지 않았습니다.

## 작은 검사 실행 방법

확인한 ML 환경은 Python 3.12.7, NumPy 1.26.4, pandas 2.2.2, scikit-learn 1.7.0입니다. 검사에는 matplotlib, Excel을 읽으려면 openpyxl도 필요합니다. 새 환경에서의 설치는 검증하지 않았습니다.

```text
python -m unittest discover -s tests -v
python -m unittest discover -s database -p test_stock_etl.py -v
```

원자료가 없으므로 이 ZIP만으로 실제 데이터 학습·378만 행 대조를 재현할 수 없습니다. 실제 MySQL의 11개 검사는 MySQL 서버를 별도로 준비하고 설정해야 하며, 위 Python 검사에는 포함되지 않습니다. `sample_stock_data.csv`는 가상 회사의 3행 합성 자료입니다. `run_isolated_mysql.py`는 Windows용 MySQL 실행 파일 등을 별도로 준비할 때 참고하는 코드입니다.

노트북에는 Excel·CSV 읽기와 출력·덮어쓰기 처리, Windows용 글꼴을 전제로 하는 부분이 남아 있습니다. 출력 위치를 확인한 뒤 실행해야 합니다. 별도 financial_data 테이블의 처리와 fin_data.txt 전체 처리는 검증하지 않았습니다. v2 평가 스크립트는 입력의 SHA-256을 확인하고 결과를 파일로 씁니다. 원본에서 결측인 3행을 원래 노트북에서 자동으로 채우는 변경은 하지 않았습니다.

## 이 배포 자료의 범위

코드는 수정 사본에서 발췌했습니다. 노트북에 저장된 출력·실행 번호·첨부·메타데이터는 배포 시 제거했습니다. `MANIFEST.json`에 배포 파일의 해시와 원본 파일과의 대응을 기록했습니다. 원본 Excel·실제 데이터 CSV·DB 파일·인증정보는 포함하지 않았습니다. 이번에 AI가 수행한 수정·검사를 제작 당시 본인이 단독으로 달성한 성과로 취급하지 않습니다.
